About OTRIS Edge

A vendor-blind, proof-driven integration platform.

OTRIS Edge transforms data from any medical device into normalized, traceable, trustworthy information — without ever locking a hospital, vendor, or developer into a single brand or protocol.

01

Vendor Blind

Works with any device, any protocol. OTRIS never assumes who made the hardware — only what the signal means.

02

Proof Driven

Evidence and validation are first-class. Every normalization carries a compatibility status and an immutable reference.

03

Device Agnostic

Not limited to one brand or manufacturer. New protocols extend the parser layer without touching the core.

04

Open Source

Transparent, community-powered. Apache 2.0 licensed — read it, fork it, ship it.

Core Concepts

The tuning path — from raw signal to canonical truth.

Seven layers, each with its own boundary and color. Data only moves forward through a validated interface — never around one.

1 · PROTOCOL LAYER
Protocol Family Boundary
HL7 v2.x · Future Protocol A/B · Extensible
2 · PARSER LAYER
Generic Parser Interface
Adapter Parser · HL7 v2 Generic Parser · Other Parsers
3 · DATA CONTRACT
Universal Data Contracts
ParseResult · ParsedObservation · UnknownFields (Preserved)
4 · MAPPING LAYER
Mapping Profile Boundary
Mapping Profile · Northern Mapping Profile · Other Mappings
5 · DEVICE PROFILE
Device Profile Authority
Device Profile · Northern Device Profile · Other Profiles
↓ ↓ ↓ ↓ ↓
6 · ORCHESTRATION LAYER
Runtime Normalization Orchestrator
Runtime Context (Device ID, Profile, Evidence Refs) → Normalization Orchestrator (resolves profiles, validates authorities, normalizes observations, preserves unknowns) → Normalization Result (observations, failures, provenance)
↓
7 · CANONICAL & PROOF LAYER
Proof-Driven Validation (Outside Orchestrator)
Canonical Model (Lab) → Compatibility Status (Lab / Real-Device / Production Validated) → Validation Evidence (source, collector identity, immutable URI/hash)
NOT IN SCOPE — BY DESIGN
  • Compatibility Status
  • Validation Evidence
  • Network / MLLP
  • Device Discovery
  • Protocol Framing
  • Transport Layer
Quick Start

Five steps from device to trusted observation.

01

Connect any device

e.g. Northern Meditec — or write your own adapter for a device we've never seen.

02

Parse using the generic parser

The Adapter Parser interface turns raw protocol frames into a ParseResult.

03

Map using an approved profile

Mapping profiles translate device fields into canonical observations.

04

Normalize via the runtime orchestrator

Profiles and authorities are validated before anything is normalized.

05

Get normalized, traceable observations

Every output carries its provenance back to the runtime device ID.

tuner.logotris-edge/agent
$ otris-edge run --device northern-meditec
▸ protocol: HL7v2.x detected
▸ parser: generic_hl7v2 attached
▸ mapping: northern_mapping_profile
▸ orchestrator: resolving authorities…
✓ normalized_observations: 14
✓ unknown_fields preserved: 3
▸ status: LAB_VALIDATED
G4 392Hz → SIGNAL NORMALIZED
